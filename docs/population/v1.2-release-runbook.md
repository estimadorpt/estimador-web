# Population v1.2 — release-day runbook (estimador-web)

Window: 4 to 8 December 2026; launch Wednesday 9 December. The site code for the new questions is
already on main (contract: `v1.2-parish-questions.md`), so release day is a data sync and a few
constants. **The bump itself waits for Bernardo's word.** Nothing here is published before it.

## 0. Before you start

- The producer's handoff exists: the v1.2 public bundle (`public_bundle_v1.2.x.json`,
  `experiences_v1.2.x/`, `responses_v1.2.x/`, `scorecard_v1.2.x.json`) with the §2 recipes, the
  census-facts parish responses (`census_attributes_v1.2_parish.parquet` turned into responses by
  the producer, not by the site), the income responses, the release package and `release.json`
  with every file's size, sha256 and licence.
- The producer says whether `household_type` passed the verify-release cross-check (contract §2b).
- Work on a branch; never on main.

## 1. Sync

1. `scripts/sync-population.py`: update `PINNED` (the handoff's sha256 prefixes) and the release
   number; check `GAME_EPOCH` still reads `POPULATION_GAME_EPOCH` = **2026-10-06** and the deck's
   day 0 is still **030857** (the calendar must not move).
2. `./scripts/sync-data.sh population` → `public/data/population/v1.2.x/`.
3. Read the sync's own checks: every parish has every recipe in `recipe_order`, every response
   rebuilds byte for byte.

## 2. Constants

- `src/lib/config/population.ts`: `POPULATION_RELEASE`, `POPULATION_PUBLISHED`, the file list in
  `POPULATION_DOWNLOADS.files` (sizes from `release.json`; add the layer files with keys
  `census_facts`, `income`, `vote`, `attitudes` and their licence: EEP vote columns
  `CC BY-NC 4.0`, ESS attitude columns `CC BY-NC-SA 4.0`).
- `scripts/validate-data.mjs`: the release number.
- `src/components/population/quality/copy.ts`: `SUPERSEDED` (v1.2 supersedes v1.0.3; v1.1 was
  never released), `REPLACED`, `GITHUB_PUBLISHED` (GitHub's upload date if it differs).
- `src/lib/population/labels.ts`:
  - `VALUES.income_band`: already the income thread's seven bands (codes 0–6); check them against
    the shipped label map and the income response's codes (the sync's code check fails otherwise).
  - `INSTITUTIONAL_AFTER_FIT`: empty it (v1.2 writes collective-quarters residents inside the
    generator, DECISIONS §65), and reword `INSTITUTIONAL_RECORDS` and the `is_institutional` /
    `nucleus_id` dictionary overrides from the model card.
  - `RECIPE_CAVEAT.household_type` and `SITE_NOTES['households.hh_type_top']`: delete both if the
    release passed the cross-check (contract §2b).
- `src/components/population/data/dictionary.ts`: re-read every `DESCRIPTION_OVERRIDES` entry
  against v1.2's `metadata.json`: tenure, rooms, occupation, industry, work place and transport are
  **fitted per parish** in v1.2 (the v1.0.3 overrides say "not fitted": wrong for v1.2). Drop
  `SITE_LABEL_MAPS` entries the producer now ships.
- Country-group labels for the census-facts dictionary (the eight groups INE's code list has no
  Portuguese name for; members in the census thread's table):
  BENL "Bélgica, Países Baixos e Luxemburgo", EU other "Outros países da UE", EAST "Europa de
  Leste", USCA "Estados Unidos e Canadá", SASIA "Sul da Ásia", AMER "Outros países da América",
  AFR "Outros países de África", OTHER "Outros países". Check each against the members list
  before using it.

## 3. Copy that changes with the release

- `/populacao/metodologia`: a short "O que há de novo na v1.2" section (the fitted work tables,
  the homes, collective-quarters residents in the generator, the census facts and income layers,
  the modelled section); keep the story untouched.
- `/populacao/qualidade`: the newly evaluated tables (work, homes) in `CONSTRAINT_LABEL` and the
  fit charts, from v1.2's scorecard.
- `/sobre`'s population row, the homepage panel (`home.population*` in `messages/*.json`), the
  hub's lede: release number and date come from config; check the counts sentences.
- `/populacao/dados`: the files table prints each file's licence; the licence paragraph names the
  ESS terms (CC BY-NC-SA 4.0) for the attitude file.
- The one site-wide licence answer must agree with `/dados`: `/sobre#reutilizar`,
  `SHORT_ATTRIBUTION` and `releaseCitation` (`src/lib/population/cite.ts`), and CLAUDE.md's
  "Licences" paragraph (the attitude file is CC BY-NC-SA 4.0 because ESS's terms require it; the
  launch brief of 18 Nov names it).
- CLAUDE.md's "Population section": the release number, the counts, the caveat paragraph.

## 4. Checks

1. `npm run og` (regenerates the population card from the new `meta.json`; commit the cards, the
   manifest and `staticwebapp.config.json` together).
2. `npm run check`.
3. Export build from a copy: `git archive HEAD` into a scratch folder, symlink `node_modules`,
   `npm run build` (runs `check:export`: budget, titles).
4. Phone check of one parish page at 360 and 390 px: every section, the Modelado lede, a work card
   with 22 industry bars, the table twins.
5. Push the branch, open the PR; after the preview deploys, `npm run smoke -- --base <preview>`.
6. Ask Bernardo for the go (one card). Merge on his yes; the deploy is the release.

## 5. After

- Old permalinks: if the producer shipped an id map (contract §4 item 7), wire it into
  `consulta/other-release.ts`; otherwise old `v1.0.3` links keep their "other release" page.
- Tell the notes thread the bundle is live (note 3's figure comes from it).
